## BUGTRK-21: Completion % outside the Projects card

**Cause.** `client/src/features/insights/pages/DashboardPage.tsx:134` uses `grid gap-1 lg:grid-cols-2 lg:gap-x-4`, which has no column template below `lg`. The implicit `auto` column takes the min-content width of the widest `ProjectProgressRow`:

- That width is the name at full `nowrap` width, plus the key, the badge and the `w-12` %.
- So on phones and small tablets the row grows wider than the card, and the % is pushed past the card's edge.

**Fix.** Use `grid grid-cols-1 gap-1 lg:grid-cols-2 lg:gap-x-4`. Tailwind v4 `grid-cols-1` is `minmax(0, 1fr)`, so the row is capped at the card's width and the name truncates.

**Test.** In `e2e/mobile-shell.mobile.spec.ts` (all phone sizes), seed a project with a long name. On `/`, check that every Projects row's % `getBoundingClientRect().right` is ≤ its `[role=region]` card's right edge. Also compare Playwright screenshots at 375, 744, 1024 and 1440 px before and after.

## BUGTRK-8: No focus zoom on mobile

**Cause.** iOS zooms in when the focused field's font-size is under 16px. `client/src/styles/index.css:84-90` forces 16px on `input, select, textarea` only at `max-width: 767px`. As a result:

- **Every Tiptap editor zooms, on every device.** The `RichTextEditor.tsx:288` wrapper is `text-sm`, and the editor itself is a contenteditable. That covers the description, the comment composer (which `TaskDetail.tsx:39` also focuses programmatically), bug details and quick create.
- **Touch screens wider than 767px** (iPhones in landscape, iPads) get the raw 14px `text-sm`.
- **Larger fields are shrunk.** The blanket `!important` forces down fields that are deliberately bigger: the task title (`TaskDetail.tsx:96`, `text-xl`) and `OneTimeCodeInput.tsx:35` (`text-lg`).

**Fix.** In `@layer base` of `index.css`, replace that block with:

```css
@media (any-pointer: coarse), (max-width: 767px) {
  input,
  select,
  textarea {
    --text-xs: max(1rem, 16px);
    --text-sm: max(1rem, 16px);
  }

  [contenteditable] {
    font-size: max(1rem, 16px);
  }
}
```

- `text-xs` and `text-sm` resolve `var(--text-*)` on the field itself, so 16px becomes a floor. Small fields grow to 16px and `text-lg`/`text-xl` fields keep their size. Line heights are ratios, so they stay correct.
- `max(1rem, 16px)` keeps Large touch size working and never drops below 16px.
- No `maximum-scale=1`. It blocks pinch zoom on Android and fails axe's `meta-viewport` rule in `e2e/a11y.spec.ts`.

**Test.** New `e2e/no-zoom.mobile.spec.ts`, in the style of `undersizedControls` (`e2e/mobile-shell.mobile.spec.ts:7-30`).

- **Pages:** `/`, the board, a list with a task open (description, plus the composer opened via Comment), `/settings/account`, the shopping list, and the calendar event modal.
- **Selector:** `input:not([type=hidden],[type=checkbox],[type=radio],[type=color],[type=file]), select, textarea, [contenteditable=true]`.
- **Check:** the computed `fontSize` is ≥ 16.
- Run the sweep again at a landscape size, 932×430.

## BUGTRK-18: Hide project settings the role can't change

**Rule.**

- A control the caller can't use isn't rendered at all; it isn't shown disabled or read-only.
- A tab with nothing usable isn't listed, and its URL redirects to the first usable tab.
- The project's **Settings** tab is hidden when no settings tab is usable.

The server guards in `projects/access.ts` already match this.

**`client/src/features/projects/settings/settingsTabs.ts`.** `settingsTabs(project, telegram)` returns the ordered tabs the caller can use. Permissions are checked with `can(mask, …)`, where `mask = isArchived ? 0 : permissions` (the same as `useProjectPermissions`). Restore is the exception and uses the raw mask.

| Tab         | Visible when                                                                                                                                 |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| General     | `project.edit`                                                                                                                               |
| Workflows   | `project.manage_workflow`                                                                                                                    |
| Labels      | `project.manage_labels`                                                                                                                      |
| Members     | `project.manage_members`                                                                                                                     |
| Roles       | `project.manage_roles`                                                                                                                       |
| Telegram    | the feature is on, the project isn't archived, and the bot is allowed (from the existing telegram settings query) or the caller is the owner |
| Danger zone | raw `project.archive`, owner (Delete) or non-owner (Leave), so always for at least one reason                                                |

- `ProjectSettingsLayout.tsx` builds `TabLinks` from it.
- New `SettingsTabGuard.tsx` wraps the `router.tsx` settings children and the index route. If the current tab isn't in the list, it `Navigate`s to the first visible tab.
- `ProjectLayout.tsx:165` also drops `settings` when the list is empty.

**Inside visible tabs: remove, don't disable.**

- **General / Workflows / Labels:** remove the `deniedReason`, `fieldset disabled` and read-only branches, since these tabs only show when the caller can edit them.
- **Members:**
  - The role picker shows only on rows where `canManage(member)`; other rows show the role as plain text.
  - Leave project moves out of this tab.
- **Danger zone:**
  - Archive/Restore needs raw `project.archive`.
  - Delete is owner-only.
  - New **Leave project** section for non-owners, reusing the existing leave mutation and confirm dialog from `MemberSettings`.
- **Roles:**
  - Hide the owner role and any role that isn't a subset of the caller's mask, since the caller can't edit those.
  - Inside an editable role, hide permission rows the caller doesn't hold. They are always off in that role and the caller can't turn them on.
- **Telegram:**
  - Chats the caller can't edit are filtered out in the `GET …/telegram` SQL, so they're never sent.
  - "Add to a group" is already hidden without `project.edit`.

## BUGTRK-11: Card images and attachments persist

**Root cause, confirmed in the Render logs.** On 29–30 Oct, `GET /api/attachments/:id` failed with `ENOENT … /var/data/uploads/attachments/2026-10/*.png`.

- The service runs on Render's free plan, with no disk.
- Every deploy, restart or wake-up starts with an empty upload folder.
- Files that are already lost can't be recovered.

### 1. Storage on Cloudflare R2

- **Dependency:** `aws4fetch@1.0.20` in `server/package.json`. It is a ~2 KB SigV4 signer over `fetch`, instead of the multi-MB AWS SDK.
- **`server/src/config.ts`:** optional `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` and `R2_BUCKET`, set all or none. They derive `config.r2 = { endpoint: https://<account>.r2.cloudflarestorage.com/<bucket>, … } | null`.
- **`server/src/lib/storage.ts`** keeps its exports so callers barely change:
  - `moveIntoStorage(tmp, key, mime)` / `copyIntoStorage(src, key, mime)`: with R2, a streamed `PUT` (`Readable.toWeb(createReadStream)`, `duplex: 'half'`, `Content-Type` and `Content-Length` set), then the temp file is removed.
  - `removeStored(keys)`: with R2, one `POST ?delete` (DeleteObjects, XML body plus `Content-MD5`) per 1000 keys. Failures are logged as today.
  - **New `sendStored(req, res, key)`**, which replaces `res.sendFile(storagePath(key))` in `attachments/routes.ts:63` and `users/routes.ts:59` (avatars are lost the same way today).
    - With R2, it streams a `GET` back through the API and passes `Range` / `If-None-Match` through.
    - It copies the status (200/206/304) and the `content-type`, `content-length`, `content-range`, `etag`, `last-modified` and `accept-ranges` headers.
    - An R2 404 becomes `HttpError(404)`.
    - Files stay same-origin and behind the existing auth checks, with no CSP change.
  - Without R2 it behaves exactly as today (local disk), for dev, tests and a Blueprint with a disk. The multer temp folder stays local.
- **Callers:**
  - `upload.ts` passes `type.mime`.
  - `demo/generator.ts` passes the mime type to `copyIntoStorage`.
- **Config and docs:**
  - `render.yaml`: drop `disk`, add the 4 R2 vars (`sync: false`).
  - `.env.example`: add the 4 vars.
  - `docs/setup-requirements.md` §3: replace with "File storage on Cloudflare R2".
  - `README.md`: update the deploy section.

### 2. Other attachment bugs

1. **Missing file returns 404, not a logged 500.** In `middleware/errorHandler.ts`, before the 500 fallback, answer any error with a numeric `status` from 400 to 499 with that status, without logging it as unhandled.
2. **Description save race.** `RichTextEditor.tsx` saves only on blur. Pasting an image and closing the drawer before the upload finishes loses the image markdown. Move the blur logic into one `save(editor)` and call it from `onBlur`, after `insertFiles` inserts content, and from a `useEffect` cleanup (flush on unmount).
3. **Comment edits drop their images.**
   - `updateCommentSchema` (`shared/src/schemas/collab.ts`) gains `attachmentIds`.
   - The comments route and service link them with the existing `linkCommentAttachments`.
   - `CommentsSection.tsx:49` passes the ids.
   - Today those images stay pending, and `PURGE_PENDING` deletes them after 24 h.
4. **Copies keep their own images.** Duplicating a task or spawning a recurrence copies the description, but its images stay on the original, so deleting the original deletes the copy's images.
   - New migration: `CREATE INDEX attachments_storage_key_idx ON attachments (storage_key);`.
   - **Copy the referenced rows.** In duplicate (`tasks/service.ts:136-146`) and `SPAWN_RECURRENCES` (`:170-182`), add one CTE in the same transaction: `WITH src AS (SELECT a.id old_id, gen_random_uuid() new_id, … JOIN new tasks … WHERE a.comment_id IS NULL AND strpos(copied text, a.id::text) > 0), ins AS (INSERT … SELECT … FROM src) SELECT old_id, new_id, task_id FROM src`. It copies only the attachment rows the text references, with the same `storage_key` and no file copy.
   - **Point the copy at the new rows.** Swap the ids in the copied text in JS, then write it back with one `UPDATE tasks … FROM unnest(...)`, which also bumps `attachment_count`. This only runs when rows were copied.
   - **Delete a file only when no row uses it.** Every file removal (attachment, task, project, `PURGE_PENDING`, demo reset) goes through `removeUnreferenced(keys)` in `attachments/service.ts`. It runs `SELECT k FROM unnest($1::text[]) k WHERE NOT EXISTS (SELECT 1 FROM attachments WHERE storage_key = k)` and then `removeStored`.

  - `PUT` goes to `<account>.r2.cloudflarestorage.com/<bucket>/<key>`, signed, with the content type;

## BUGTRK-20: Verification email reaches only the account owner

**Code fixes, so a failure is visible and harmless:**

1. `lib/mailer.ts`: in production with no transport, throw instead of logging the link and reporting it as sent.
2. `auth/service.ts` (`sendVerificationEmail` / `sendPasswordResetEmail`): void the other tokens only after the send succeeds (`… AND id <> $3`), so a failed send keeps the previous link working.
3. `auth/routes.ts`:
   - `/register` returns `{ user, verificationSent }`. When it's false, the client shows a toast: "We couldn't send the verification email. Use Resend link in the banner."
   - `/forgot-password` catches the send error, logs it, and still returns 204. Today it returns 500, which also reveals that the account exists.

**Tests.** In `server/test/auth.test.ts`:

- a Resend 403 on register returns 201 with `verificationSent: false`, and the old token still works;
- forgot-password with a failing transport returns 204.
